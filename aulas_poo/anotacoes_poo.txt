O que é?
POO - Programação orientada a objeto
OOP - Object oriented program

Características de sistemas POO:
Confiabilidade - não preciso alterar n partes do sistema, contanto que eu siga as regras
Oportunidade - ao dividir um sistema em partes, cada uma delas pode ser desenvolvida em paralelo
Manutenível - atualização fácil do software, onde todos os benefícios otimizam as demais partes
Extensível - sistema não deve ser estático, tudo deve mudar e crescer para permanecer útil
Reutilizável - objetos que são criados para um sistema, podem ser aproveitados em outros sistemas
Natural - o sistema é fácil de entender, dando maior atenção as funcionalidades e não a implementação'

Classe
Formato a ser seguido sempre que eu precisar fazer objetos do mesmo tipo, desde que tenham mesmas características
Exemplo: uma mesma forma de bolo que pode assar bolos de chocolate e de cenoura

Ao determinar uma classe eu devo pensar no objeto lá no futuro, e ele deve ter 3 coisas:
- nome da classe
- características da classe -> atríbuto
- coisas que eu posso fazer -> método

Exemplo:
classe - assar_biscoito
atríbuto - tamanho, massa, peso, cobertura
método - cozinhar(), congelar()

Instância
Seguir o padrão definido na classe, para criar um objeto

Objeto
Coisa feita a partir de uma classe que pode ser descrita por meio de atributos, métodos e estado atual

Variável simples é o aquilo que vc declara (e nomeia) que ocupará um espaço em seu computador.
Para declarar uma variável é necessário nomeá-la (de acordo com algumas regras). Exemplo: cidade = 'São Paulo'

Já variável composta é aquela que consegue armazenar mais valores. Aqui surgem as arrays Exemplo: cidades = ('São Paulo', 'Rio de Janeiro', 'Sorocaba').

Uma variável que consegue guardar dando dados qto funções é o OBJETO.

Objeto é similar de variável

Estrutura obrigatória:

- área de declaração de classes -> começa com class, nome deve começar com letra maiúscula, não esquecer os dois pontos
class MinhaClasse:

- área de declaração de atributos e métodos

- área de declaração de objetos -> momento em que vc chama (ou instância) a classe criada, por isso se faz necessário o uso dos parênteses (bem como função).
objeto = MinhaClasse()

Dunders:
São métodos especiais que começam e terminam com dois sublinhados (ex: __init__) e permitem personalizar o comportamento de classes, fazendo com que objetos interajam com funções e operadores internos da linguagem

Exemplos:
__init__: Inicializa o objeto.
__str__: Retorna uma representação em string legível (usado por print()).
__len__: Define o comportamento para a função len().

Método = função
Atributo = variável

Pilares da POO:
- Abstração: capacidade de simplificar as coisas e deixar o redundante para trás
- Encapsulamento: proteção do seu código;
- Herança: hierarquia dos dados
- Polimorfismo: permite que vc execute coisas do mesmo nome de maneiras diferentes

Herança:
Relacionamento do tipo "é UM" entre itens gerais (ancestrais) e tipos mais específicos (descendentes) desses itens, que herdam atributos e métodos dos níveis superiores.

Principais vantagens:
- reutilização de código;
- organização hierárquica;
- facilidade de manutenção;
- extensibilidade;
- suporte ao polimorfismo.

Em termos mais simples, herança permite receber características e comportamentos dos "pais", mas também criar suas próprias características.

Herança é representada por uma seta para cima, com uma seta de triângulo vazado. A classe acima da seta é a superclasse (classe base, classe mãe, ancestral) e a abaixo, subclasse (classe derivada, descendente, classe filha).

A subclasse pode ser superclasse de outras classes.

Abstração:
É a prática de ignorar o irrelevante e focar no estritamente essencial.
Exemplo: você não precisa entender o funcionamento interno de uma geladeira para poder utilizá-la.

Principais vantagens:
- maior legebilidade;
- padronização;
- simplificação;
- segurança.

Classe abstrata é aquela que não serve para gerar objetos, e sim para servir de base para todas as subclasses criarem objetos.

Exemplo: numa classe abstrata "controle remoto genérico", ela terá como funções básicas ligar, desligar, aumentar e diminuir volume, etc. Entretanto cada uma dessas funções será específica para cada controle remoto (diferente entre marcas, por exemplo).

Essas funções (ligar, desligar, aumentar e diminuir volume) são chamadas de métodos abstratos.

As classes que efetivamente vão virar objetos são chamadas "classe especializada".

Método concreto é aquele que você determina na classe mãe, exemplo: na classe Pessoa, todos fazem aniversário, não há como pular aniversários ou fazer n vezes num ano.

Método abstrato já é o método em que você "declara" na classe mãe, mas que poderá ser desenvolvido de formas diferentes entre as subclasses, exemplo: na classe Pessoa, todos estudam, entretanto, cada um deles pode estudar para alguma coisa diferente, como estudar para prova, estudar para um concurso, estudar por hobby.
Esse método é representado por {abstract} no código, e chamamos também de interface pública. O método criado deve ser obrigatóriamente utilizado nas subclasses.

DRY - Don't repeat yourself, não se repita
ABC - Abstract base classes

Encapsulamento:

O encapsulamento visa manter a integridade do sistema, protegendo o estado interno do objeto contra interferências externas. Exemplo prático: ao apertar um botão, ele executa X ação; você não precisa saber dos detalhes de funcionamento do objeto (botão), apenas necessita apertá-lo para a execução da ação. Isso evita problemas, durante a ação.

Principais vantagens:
- Segurança e controle;
- Facilidade de manutenção;
- Flexibilidade e reutilização;
- Redução de efeitos colaterais.

Para proteção do código, precisamos nos atentar:
- Visibilidade de atributos;
- Acesso aos dados protegidos.

Existem 3 tipos de visibilidade:
- público/public (+): visível em tudo o projeto, mesmo fora das classes;
- protegido/protected (*): visível apenas no escopo do projeto (classes mãe e filhas);
- privado/private (-): visível apenas na classe mãe;

Consenting adults: liberdade com responsabilidade, no lugar de bloquear o acesso, o desenvolvedor ao ver a classificação de privacidade deve pensar "hmm, não devo mexer nisso".

Os sinais de Python são diferenciados:
- público/public (nada a frente do atríbuto);
- protegido/protected (_);
- privado/private (__);

Existem duas maneiras de criar acessos aos dados encapsulados:
- Uso de getters e setters;
- Uso do decorador property.

Getters e setters são conhecidos como métodos acessores de dados.
